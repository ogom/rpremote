# IMU姿勢3Dモデル

[English](README.md)

[`model.pde`](model.pde)は、Pico 2から受信したroll、pitch、yawを3Dのボードモデルへ反映します。青い直方体がボード、左側のHUDが現在値、右上の短い3軸が固定されたワールド座標です。

## 3Dモデルの見方

モデルと座標軸には次の色を使います。画面左側の凡例にも同じ対応を表示します。

| 色 | 軸 | 姿勢 |
| --- | --- | --- |
| 赤 | X | roll |
| 緑 | Y | pitch |
| 青 | Z | yaw |

ボードから伸びる長い3軸はセンサーと一緒に回転するローカル座標です。画面右上の短い3軸は回転しないワールド座標で、ボードが基準姿勢からどのように回転したかを比較できます。

Z-upのセンサー座標をProcessingへ表示するため、センサーの+Xを画面右、+Yを奥行き、+Zを画面上へ対応させます。基準姿勢では青いZ軸の丸がモデルの上に表示されます。

コードはこの座標変換に沿ってyawを表示上のZ軸、pitchをY軸、rollをX軸へ適用します。画面左側には角度のほか、加速度、角速度、IMU内部温度を表示します。加速度や角速度が3Dモデルの位置を直接動かすのではなく、Pico 2側で推定したroll、pitch、yawがモデルの向きを決めます。

## 航空機で考えるroll、pitch、yaw

航空機に例えると、次の動きです。

| 姿勢 | 航空機の回転軸 | 3Dモデルの動き |
| --- | --- | --- |
| roll | 機首から尾翼へ通る前後軸 | 左右の翼を傾けます。 |
| pitch | 左翼から右翼へ通る左右軸 | 機首を上げ下げします。 |
| yaw | 機体を上下に通る垂直軸 | 機首を左右へ向けます。 |

この対応は、センサーの+Xを機首方向、+Yを翼方向、+Zを機体上方向に取り付けた場合です。実際のセンサーの設置方向が異なる場合、3Dモデルと実物の動きを一致させるにはPicoRuby側で軸と符号を変換する必要があります。

現在の姿勢推定はZ-upを水平姿勢として扱います。Y-upで設置するとセンサーが正常でも約90 degree傾いたモデルになります。

### Unityとの違い

UnityもXを赤、Yを緑、Zを青で表示するため、軸の色はこのProcessingモデルと同じです。ただし、Unityは一般に+Yを上、+Zを前とするため、航空機の動きとして見た回転軸は異なります。

| 色と軸 | このProcessingモデル（Z-up） | Unityの一般的な見方（Y-up、Z-forward） |
| --- | --- | --- |
| 赤 X | roll | pitch |
| 緑 Y | pitch | yaw |
| 青 Z | yaw | roll |

Unityの`Transform`は回転をX、Y、Zとして扱い、roll、pitch、yawは正式なプロパティー名ではありません。この表は、Unity上のモデルを航空機として扱う場合の一般的な対応です。このProcessingモデルでは、センサーと一致する航空機／IMUのZ-up表記を使用します。

## 姿勢値の性質

rollとpitchは、Gyroscopeで短時間の回転を追跡し、Accelerationが示す重力方向で長時間のずれを補正します。

BMI270とMPU6050には磁気センサーがないため、yawは起動時を基準にした相対角度です。時間とともにドリフトし、北を基準にした絶対方位にはなりません。

## 受信データとの対応

現在のPicoRubyストリームは次のCSVを20 Hzで送信します。

```text
IMU_DATA,sensor,timestamp_ms,temperature_c,ax_g,ay_g,az_g,gx_dps,gy_dps,gz_dps,q0,q1,q2,q3,roll_deg,pitch_deg,yaw_relative_deg,posture,gesture
```

3Dモデルの回転には`roll_deg`、`pitch_deg`、`yaw_relative_deg`を使用します。HUDとProcessing Consoleにはセンサー名、時刻、温度、加速度、角速度も表示します。`q0`〜`q3`、`posture`、`gesture`は受信しますが、このスケッチの表示には使用しません。

PicoRuby側が姿勢列を含まない短い形式を送った場合に限り、Processing側の相補フィルターで姿勢を推定し、最初の100サンプルでジャイロバイアスを求めます。現在のストリームは姿勢列を含むため、Pico 2側で推定した値を優先します。

## 実行と確認

Processing 4で[`model.pde`](model.pde)を開いて実行します。スケッチは`/dev/cu.usbmodem101`を優先し、見つからない場合は最初の`/dev/cu.usbmodem*`を選択します。

Processing Consoleには、受信したセンサー名、時刻、加速度、角速度、姿勢を1秒ごとに表示します。モデルが動かない場合は、Consoleで選択されたポートと`IMU received`の表示を確認してください。Processingがポートを使用している間は、同じポートで`rpremote monitor`を実行できません。

`R`キーは、短い入力形式で使用するProcessing側の相補フィルターをリセットします。現在のPicoRubyストリームが行う2秒間のジャイロキャリブレーションや、Pico 2側の姿勢推定はリセットしません。それらを最初からやり直す場合はストリームを再起動し、センサーを2秒間静止させます。
